## Запрос / мотивация
Результат исходного заезда (0005) — только «врезался в стену»: ни скорости, ни места на трассе,
ни времени. Любое следующее изменение (тормоз и т.д.) нужно оценивать по цифрам, а не на глаз.
Кроме того, CSV и итоговая сводка позже станут основой фитнес-функции для эволюционного подхода.

Нужно: опция `--log <file.csv>` у `snakeoil3_gym.py`, которая пишет телеметрию каждого шага в CSV
и в конце заезда печатает сводку. Без `--log` поведение драйвера не меняется.

## Что меняем
`snakeoil3_gym.py`:
- Новая опция командной строки `--log, -l <file.csv>` (в `getopt` рядом с остальными, строка
  в `--help`). Путь сохраняется в `Client.logFile` (по умолчанию `None`). Сигнатура конструктора
  `Client` не менялась, протокольная часть (`get_servers_input`, `respond_to_server`, разбор/сборка
  сообщений) — тоже. `drive_example()` не трогали.
- Новый класс `TelemetryLogger` (только стандартная библиотека, `csv`):
  - CSV, первая строка — заголовок, далее одна строка на шаг. Колонки:
    `step, curLapTime, lastLapTime, distFromStart, distRaced, speedX, speedY, trackPos, angle,
    track_ahead (track[9]), track_min (min(track)), rpm, gear (датчик), damage,
    steer, accel, brake, gear_cmd` (команды — уже после `clip_to_limits`, т.е. то, что ушло серверу).
  - Папка для файла создаётся автоматически.
  - `flush` каждые `LOG_FLUSH_EVERY` строк; `close()` идемпотентен.
  - Сводка в консоль: число шагов, итоговый `distRaced`, последняя позиция, максимальная `speedX`
    и где (`distFromStart`, `curLapTime`), первый вылет (`|trackPos| > OFFTRACK_TRACKPOS`) —
    `distFromStart`, `speedX`, `curLapTime`, шаг; число шагов вне трассы и число отдельных вылетов;
    первое увеличение `damage` с теми же полями; итоговый `damage`; пройденные круги и их время
    (по изменению `lastLapTime`), лучший круг. Если данных нет — сводка так и говорит.
- Главный цикл (`__main__`): логгер создаётся только при `--log`; строка пишется после
  `respond_to_server()`. Цикл обёрнут в `try/finally` — CSV закрывается и сводка печатается
  при нормальном окончании, при `***shutdown***` от сервера и при Ctrl+C. После shutdown
  (`C.so is None`) устаревшие данные не логируются.

`.gitignore`: добавлено `runs/` — папка для CSV заездов, в репозиторий они не попадают.

### Параметры (новые константы вверху файла, на вождение не влияют)
| Параметр | Было | Стало | Почему |
|----------|------|-------|--------|
| `LOG_FLUSH_EVERY` | — | 50 | сброс CSV на диск ≈ раз в секунду |
| `OFFTRACK_TRACKPOS` | — | 1.0 | `|trackPos| > 1` — машина вне полотна |
| `LOG_TRACK_AHEAD_IDX` | — | 9 | луч `track` прямо вперёд (0°) |

## Как проверить
Выполнено:
- `python -m py_compile snakeoil3_gym.py` — без ошибок.
- `python snakeoil3_gym.py --help` — новая строка `--log` на месте.
- Офлайн-самопроверка `TelemetryLogger` на синтетических данных (300 шагов): 301 строка в CSV,
  верно посчитаны вылеты (15 шагов / 2 вылета), первое повреждение, круг, макс. скорость;
  пустой заезд даёт корректную сводку.

Для Hlib (Windows, TORCS → Race → Practice, corkscrew, scr_server → New Race), во втором cmd:
```
cd /d C:\RaceYourCode\gym_torcs
C:\torcs-env\Scripts\activate
python snakeoil3_gym.py --log runs/0006-baseline.csv
```
Успех: файл `runs/0006-baseline.csv` создан, в конце (или после Ctrl+C) в консоли сводка
`===== Run summary ... =====`. Драйвер тот же, что в 0005, — ожидаем тот же вылет в повороте,
но теперь с цифрами. Дополнительно: запуск без `--log` ведёт себя как раньше.
