# Спецификации изменений

Каждое осмысленное изменение проекта (код, параметры драйвера, конфиги трассы,
инфраструктура) фиксируется здесь.

## Структура

```
specs/
├── README.md        — этот файл (правила)
├── CHANGELOG.md     — хронологический журнал: одна строка на каждую спеку
├── _template.md     — шаблон новой спеки
└── NNNN-slug.md     — сами спеки (0001, 0002, ...)
```

## Правила

1. **Одно изменение — одна спека.** Номер — следующий свободный (`NNNN`, 4 цифры),
   slug — 2–5 слов латиницей через дефис: `0007-brake-before-corners.md`.
2. **Спека пишется до или вместе с кодом**, а не после коммита.
   Статус: `draft` → `in-progress` → `done` (или `dropped`, если идея не взлетела —
   такие спеки не удаляем, это тоже знание).
3. **Автор** — участник команды, отвечающий за изменение (например, `Hlib`).
4. **Параметры драйвера** (скорость, коэффициенты руля, пороги передач) записываются
   в таблицу «было → стало» и результат заезда (трасса, время круга, вылеты).
5. **Коммит ссылается на спеку**: `[0007] Brake before corners`.
   Один коммит может закрывать одну спеку; большая спека — несколько коммитов.
6. После завершения — строка в `CHANGELOG.md` (новые сверху).

## Мелочи без спеки

Опечатки, форматирование, правка самих спек, `.gitignore` — спека не нужна,
но коммит всё равно с префиксом `[chore]`.
