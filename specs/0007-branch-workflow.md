## Запрос / мотивация
Над проектом работают трое. Чтобы не мешать друг другу, у каждого должна быть своя ветка,
а `master` — оставаться общей рабочей версией.

## Что меняем
1. На GitHub созданы ветки от актуального `master`: `dev/hlib`, `dev/vladyslav`, `dev/pavlo`.
2. `CONTRIBUTING.md`:
   - раздел «Ветки»: таблица участник → ветка, первый `clone` + `checkout`, ежедневное
     `git merge origin/master` в свою ветку;
   - раздел «Отправка и слияние»: push своей ветки → Pull Request в `master` → ревью коллеги → слияние;
     без `push --force` в общие ветки и без прямых пушей в `master`;
   - спеки: номер берётся следующий свободный в `master`, при совпадении — переименовать при слиянии;
     конфликт в `CHANGELOG.md` разрешается сохранением обеих строк.

Обновление своей ветки — через `merge`, а не `rebase`: не требует `push --force` и безопаснее для новичков.

## Как проверить
`git branch -r` после `git fetch` показывает `origin/dev/hlib`, `origin/dev/vladyslav`, `origin/dev/pavlo`.

## Результат
Ветки созданы и отправлены на GitHub.

## Заметки / открытые вопросы
- Защиту `master` (запрет прямых пушей, обязательный PR) включает владелец репозитория
  в настройках GitHub: Settings → Branches → Add branch ruleset.
