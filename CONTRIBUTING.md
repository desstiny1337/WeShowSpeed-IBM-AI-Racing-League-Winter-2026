# Как мы работаем над проектом

Команда **WeShowSpeed** — IBM AI Racing League, Winter 2026.
Целевая трасса — **Corkscrew**. Драйверы — Python-клиенты для TORCS (SCR-сервер, UDP).

## 1. Перед началом работы

```bash
git checkout master
git pull --rebase origin master
```

Всегда начинайте с актуальной версии — в репозиторий пишут несколько человек.

## 2. Каждое изменение — спецификация

Любое изменение кода, параметров драйвера или конфигов гонки описывается в папке [`specs/`](specs/README.md):

1. Скопируйте [`specs/_template.md`](specs/_template.md) в `specs/NNNN-slug.md`
   (следующий свободный номер, slug — 2–5 слов латиницей через дефис).
2. Заполните: зачем, что меняем, параметры «было → стало», как проверить.
3. После заезда впишите результат (время круга, вылеты, наблюдения).
4. Добавьте строку в [`specs/CHANGELOG.md`](specs/CHANGELOG.md) (новые сверху).

Неудачные эксперименты не удаляем — ставим статус `dropped`. Это тоже знание.
Подробные правила — в [`specs/README.md`](specs/README.md).

## 3. Коммиты

Сообщения коммитов — на английском, со ссылкой на спеку:

```
[0007] Brake earlier before the corkscrew turn

Spec: specs/0007-brake-before-corkscrew.md
```

- Мелочи без спеки (опечатки, `.gitignore`, правка самих спек) — префикс `[chore]`.
- Если над изменением работали вместе — добавьте соавтора в конце сообщения:
  `Co-authored-by: Name <email>`.
- Добавляйте файлы явно (`git add <path>`), не коммитьте `__pycache__`, логи, локальные настройки IDE.

## 4. Отправка

```bash
git pull --rebase origin master
git push origin master
```

- Конфликт при rebase — разрешите его или напишите в чат команды; не используйте `push --force` без договорённости.
- **Никогда не пушьте в `upstream`** (оригинальный `ugo-nama-kun/gym_torcs`). Наш remote — `origin`.

## 5. Запуск

1. Запустите TORCS, в меню **Race → Practice → Configure Race**: трасса `corkscrew` (road), пилот `scr_server`.
   Эталонная конфигурация — [`practice.xml`](practice.xml).
2. **New Race** — TORCS ждёт клиента на UDP-порту 3001.
3. Во втором терминале запустите драйвер, например:
   ```bash
   python torcs_jm_par.py
   ```
   Опции: `-p <port>`, `-m <steps>`, `-d` (полная телеметрия), `--help`.

Без экрана (Linux / HPC) используется vtorcs из `vtorcs-RL-color/` и конфиг [`quickrace.xml`](quickrace.xml):
`torcs -T -c <dir> -p <port>`.

## 6. Код

- Параметры драйвера — константами вверху файла, с комментарием, что они делают.
- Не переформатируйте чужой код целиком: дифф должен показывать только смысловые изменения.
- `vtorcs-RL-color/` — исходники симулятора; не меняйте без отдельной спеки.

## 7. Личные файлы инструментов

Если ваш редактор или другие инструменты используют собственные локальные файлы настроек
или инструкций, не коммитьте их: добавьте их в `.git/info/exclude` (локальный аналог `.gitignore`).
В таких файлах достаточно указать: «следуй правилам из `CONTRIBUTING.md`».
